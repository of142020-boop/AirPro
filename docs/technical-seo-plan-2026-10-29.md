# خطة تدقيق وتحسين AirPro التقنية

تاريخ المراجعة: 29 أكتوبر 2026. النطاق: مشروع AirPro المحلي، موقع خدمات شفاطات وتهوية مبني بـ Astro 4.16.19 بإخراج ثابت. النسخة الحالية تبني 22 صفحة HTML، تشمل 404 وصفحة الأعمال المؤجلة. الدومين النهائي والاستضافة لم يؤكدا؛ لم يُنشر المشروع في هذه الجولة.

## النتائج المؤكدة وما لم يُقس بعد

| البند | النتيجة |
|---|---|
| البناء النهائي للمسودة | ناجح |
| فحص Astro/TypeScript | 0 أخطاء و0 تحذيرات؛ 3 ملاحظات قديمة في أدوات التحليل |
| فحص SEO | 22 صفحة: عناوين وأوصاف وH1 وروابط وIDs وأرقام واتجاه الفهرسة |
| اختبار الإطلاق | ناجح في مجلد منفصل ودومين example اختباري؛ لم يغيّر إعداد النشر |
| نموذج التواصل | فحص السكربت المبني: رقم صحيح، ترميز العربية والرموز والأسطر، منع الطلب الناقص؛ لم تُرسل رسالة |
| الهاتف | مراجعة بصرية بعرض 390px، القائمة تعمل، لا تمرير أفقي في الصفحات المختبرة |
| 404 | مسار مفقود أعاد HTTP 404 في المعاينة المحلية |
| تدقيق اعتماديات npm الحالي | 8 حزم متأثرة: 1 حرجة، 5 عالية، 2 متوسطة؛ ليست 8 هجمات مثبتة ولا تعني تساوي قابلية الاستغلال |
| CWV الميدانية وSSL والرؤوس وCDN | غير مقاسة على دومين إنتاج مؤكد |

## 1. الزحف والفهرسة

### عاجل — قبل الإطلاق

- [ ] تأكيد الدومين النهائي ونسخة HTTPS المفضلة، وضبط متغيري البناء التاليين على الاستضافة فقط عند جاهزية الموقع. example هنا مثال محجوز لا يُستخدم في النشر:

```dotenv
SITE_URL=https://airpro.example
SITE_LAUNCH_READY=true
```

- [x] البناء الافتراضي يبقى `noindex,follow` إلى حين التفعيل. عدم ضبط SITE_URL لا يولّد Canonical بدومين مختلق. تفعيل الإطلاق دون دومين يجعل البناء يفشل.
- [x] robots يسمح بالزحف حتى تُقرأ noindex؛ لا يستخدم Disallow لحجب صفحة نريد إزالة فهرستها. حماية المسودة الخاصة تُنفذ بكلمة مرور في الاستضافة، لأن noindex ليس حماية وصول.
- [ ] بعد الإطلاق، تحقق من استجابة `/robots.txt` الفعلية:

```text
User-agent: *
Allow: /
Sitemap: https://airpro.example/sitemap.xml
```

- [x] الخريطة تتولد من مسارات الصفحات، وتبقى فارغة في المسودة. صفحة الأعمال و404 مستبعدتان. بعد الإطلاق لا تشمل الخريطة إلا روابط Canonical المطلوبة للفهرسة، وتراجع HTTP 200 على الدومين الحي.
- [x] Canonical ذاتي لكل صفحة عند وجود SITE_URL. التعديلات في Layout.astro تستخدم Astro.site، ولا تعتمد على Host أو عنوان المعاينة.

```astro
---
const canonical = Astro.site
  ? new URL(Astro.url.pathname, Astro.site).href
  : undefined;
---
{canonical && <link rel="canonical" href={canonical} />}
```

- [ ] راجع تحويل HTTP إلى HTTPS وwww إلى النسخة المفضلة وشرطة النهاية، بخطوة دائمة واحدة 301 أو 308. الروابط الداخلية وCanonical والخريطة يجب أن تتفق على الشكل نفسه.
- [ ] الرابط المنقول يتحول إلى بديله الحقيقي فقط. المحذوف بلا بديل يعيد 404 أو 410. لا تحول كل الأخطاء للرئيسية ولا تجعل SPA fallback يعيد 200 للروابط غير الموجودة.

### متوسط

- [ ] إثبات ملكية الدومين في Search Console وإرسال الخريطة، وفحص الرئيسية وخدمة المطبخ والصيانة بمفتش الروابط.
- [ ] حصر روابط UTM ونسخ المسارات، ومراجعة الصفحات المكتشفة غير المفهرسة حسب الجودة والروابط والرد HTTP؛ Canonical إشارة وليس أمر فهرسة.
- [ ] تجنب خلق صفحات نتائج بحث داخلية أو فلاتر أو مواقع مناطق متشابهة دون قيمة مستقلة. بهذا الحجم ليست ميزانية الزحف عنق الزجاجة المتوقع؛ الأهم اكتشاف الصفحات واستجاباتها وجودتها.

### تحسين إضافي

- [ ] إضافة lastmod فقط من تاريخ تحديث فعلي للمحتوى، وتحليل سجلات الزحف عندما تتاح. لا تُحدّث كل التواريخ عند كل بناء.

## 2. السرعة وCore Web Vitals

### عاجل — القياس

- [ ] بعد نشر نسخة مؤقتة قابلة للقياس، شغّل PageSpeed Insights/Lighthouse على الرئيسية وخدمة المطبخ والتواصل ومقال، مع إعداد الهاتف، وكرر القياس في ظروف ثابتة.
- [ ] سجل LCP وعنصره وTTFB وطلبات الخطوط والمهام الطويلة ومواضع تحرك التخطيط. لا يُستخدم Lighthouse وحده لإثبات اجتياز INP الميداني.

| المقياس | الهدف عند الشريحة 75 من الزيارات الفعلية |
|---|---|
| LCP | ≤ 2.5 ثانية |
| INP | ≤ 200ms |
| CLS | ≤ 0.1 |

- [x] المحتوى الأساسي HTML ثابت. JavaScript الحالي محدود للقائمة وتجهيز واتساب؛ الأسئلة تستخدم details/summary دون مكتبة واجهة.
- [ ] قياس الخط الحالي: CSS يستخدم Google Fonts عبر @import، ما يضيف سلسلة طلبات وقد يؤخر رسم العنوان. استضف Cairo WOFF2 محلياً بعد توفير ملف مرخص، واقتصر على الأوزان المطلوبة، واستخدم font-display:swap. اختبر CLS لأن استبدال الخط قد يغير القياسات.

### متوسط — التنفيذ

- [ ] عند إضافة صور حقيقية، ضعها داخل src/assets واستعمل astro:assets للتحويل والأحجام المناسبة. الصورة المرشحة لـLCP تُحمّل eager وfetchpriority=high، والصور أسفل الشاشة lazy. مثال لأصل حقيقي يُضاف لاحقاً، وليس ملفاً موجوداً الآن:

```astro
---
import { Picture } from 'astro:assets';
import workPhoto from '../assets/kitchen-hood-work.jpg';
---
<Picture
  src={workPhoto}
  formats={['avif', 'webp']}
  widths={[480, 800, 1200]}
  sizes="(max-width: 700px) 100vw, 800px"
  width={1200}
  height={800}
  alt="وصف حقيقي لما يظهر في صورة العمل"
  loading="eager"
  fetchpriority="high"
/>
```

- [ ] ثبت أبعاد الصور وأماكن الفيديو والأدوات الخارجية. لا تضف عناصر فوق المحتوى بعد التحميل. حمّل الخرائط والفيديو عند الحاجة.
- [ ] احتفظ بتصغير CSS/JS الخاص ببناء Astro/Vite، واختبر Brotli/Gzip من الاستضافة عبر Content-Encoding بدلاً من إضافة ضغط ثانٍ في المتصفح.
- [ ] راقب المهام الطويلة عند إضافة أي تتبع أو دردشة، وحمل الكود غير الضروري عند الحاجة. التفاعل مع القائمة والنموذج يجب أن يبقى سريعاً على هاتف متوسط.
- [ ] إذا كانت الاستضافة Vercel، ابدأ بـCDN المدمج وتحقق من رؤوسه؛ لا يلزم إضافة طبقة CDN ثانية تلقائياً.

```text
# ملفات ثابتة أسماؤها تحتوي hash، مثل /_astro/*:
Cache-Control: public, max-age=31536000, immutable

# HTML وrobots والخريطة: نقطة بداية لإعادة التحقق من أحدث نسخة:
Cache-Control: public, max-age=0, must-revalidate
```

هذه سياسة مبدئية؛ لا تطبق immutable على ملفات تتغير مع بقاء الاسم، ولا التخزين العام على ردود مستخدمين أو بيانات حساسة. تحقق من سياسة المنصة الفعلية والإبطال عند النشر.

### تحسين إضافي

- [ ] بعد توفر زيارات، استخدم CrUX/Search Console أو قياس RUM آمن، وافصل الهاتف عن الكمبيوتر. عدم وجود بيانات يعني نقص العينة، وليس اجتياز CWV. قارن الفترات قبل وبعد الإصلاح في ظروف متقاربة.

## 3. الهيكلة والبيانات المنظمة

### عاجل

- [x] هيكل أساسي: الرئيسية ← دليل الخدمات ← خدمة متخصصة، مع المقالات مرتبطة بالخدمة المناسبة وصفحة الحجز.
- [x] محتوى خاص بكل من المطبخ والبلت إن والمسطح والهرمي والحمامات والمطاعم والصيانة والبلاورات والدكت؛ دون إعادة استخدام نفس النص عبر المواقع الأخرى.
- [x] روابط HTML عادية قابلة للزحف، وعنوان ووصف وH1 خاص بكل صفحة؛ لا توجد صور خدمات مكسورة أو صور عامة معروضة كأعمال حقيقية.
- [ ] تأكيد أن كل خدمة مهمة تصلها روابط من الدليل ومقال أو صفحة مرتبطة؛ لا تنشئ قوائم ضخمة بروابط متكررة أو صفحات منفصلة لكل تنويع لغوي للكلمة نفسها.

### متوسط

- [x] WebPage مشروط بالدومين؛ دون اختلاق عنوان أو تقييم أو سعر.
- [ ] إضافة Organization ببيانات مؤكدة، وService لكل خدمة، وBreadcrumbList يطابق مسار التصفح الظاهر. استخدم Article للمقالات عند تأكيد الكاتب والتواريخ الحقيقية.
- [ ] LocalBusiness/HVACBusiness عند توفير بيانات نشاط حقيقية، مع استيفاء الحقول المطلوبة للميزة المستهدفة. عدم وجود عنوان مؤكد لا يبرر اختلاق عنوان. Service لا يضمن نتيجة غنية خاصة في Google.

مثال JSON-LD مشروط باستبدال دومين example بدومين مؤكد، ومطابقة البيانات للمحتوى الظاهر:

```json
{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "Organization",
      "@id": "https://airpro.example/#organization",
      "name": "إير برو | AirPro",
      "url": "https://airpro.example/",
      "telephone": "+201101219418"
    },
    {
      "@type": "Service",
      "name": "تأسيس وتركيب شفاط المطبخ",
      "url": "https://airpro.example/services/home-hood",
      "provider": { "@id": "https://airpro.example/#organization" }
    },
    {
      "@type": "BreadcrumbList",
      "itemListElement": [
        { "@type": "ListItem", "position": 1, "name": "الرئيسية", "item": "https://airpro.example/" },
        { "@type": "ListItem", "position": 2, "name": "الخدمات", "item": "https://airpro.example/services" },
        { "@type": "ListItem", "position": 3, "name": "تأسيس وتركيب شفاط المطبخ", "item": "https://airpro.example/services/home-hood" }
      ]
    }
  ]
}
```

أدخل البيانات من كائنات JavaScript ثم JSON.stringify مع ترميز `<` عند استخدام set:html. اختبر الصياغة بـSchema Markup Validator، والأنواع المؤهلة بـRich Results Test؛ لا توجد نتيجة غنية مضمونة ولا وعد بميزة FAQ.

### تحسين إضافي

- [ ] مشروعات موثقة وصور بإذن العميل، ومحتوى يوضح المشكلة والحل وحدود التنفيذ. تجنب تدوير الروابط بين المواقع لمجرد تمرير إشارات ترتيب.

## 4. الجوال والأمان

### عاجل

- [ ] معالجة تقرير npm قبل الإطلاق: النسخة المثبتة Astro 4.16.19، وتقرير التدقيق يقترح ترقية رئيسية. حدّث في فرع اختبار، راجع تغييرات الإصدارات وشرط Node، ثم أعد البناء وفحص SEO والنموذج والمسارات. لا تُطبق ترقية رئيسية عمياء ولا تعتبر كل تنبيه SSR قابلاً للاستغلال في نشر static.

```powershell
npm view astro version engines
npm outdated
npm audit --omit=dev
```

- [ ] إكمال مطابقة النشرات الأمنية مع الميزات الفعلية: المشروع إخراج ثابت دون خادم SSR منشور. خادم التطوير يبقى محلياً؛ ملفات dist وحدها هي مخرجات الاستضافة العامة.
- [x] اختبار الهاتف 390px والقائمة والحقول ذات labels. اختبر أيضاً 320px و768px و1440px والتكبير 200% ولوحة المفاتيح ووضوح التركيز وحجم مناطق الضغط.
- [ ] راجع تماثل النص والروابط والبيانات المنظمة بين الهاتف والكمبيوتر؛ المحتوى الأساسي لا ينتظر نقرة أو JavaScript ليظهر.
- [ ] تأكد من شهادة HTTPS وتجديدها وعدم وجود mixed content، ومن عدم نشر .env أو مفاتيح أداة الكلمات أو أدواتها الخاصة ضمن جذر الاستضافة.
- [ ] تحقق من HSTS الموجود في الاستضافة أولاً. لا تضف includeSubDomains أو preload حتى تتأكد من جاهزية كل النطاقات الفرعية. على Vercel يوجد HSTS افتراضياً، ويجب فحص الرد الحقيقي.

### متوسط

عند اختيار Vercel، مثال رؤوس مقترح يراجع مع إعداداته القائمة قبل دمجه في vercel.json:

```json
{
  "headers": [
    {
      "source": "/(.*)",
      "headers": [
        { "key": "X-Content-Type-Options", "value": "nosniff" },
        { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" },
        { "key": "X-Frame-Options", "value": "DENY" },
        { "key": "Permissions-Policy", "value": "camera=(), microphone=(), geolocation=()" },
        { "key": "Content-Security-Policy-Report-Only", "value": "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data:; connect-src 'self'; base-uri 'self'; object-src 'none'; frame-ancestors 'none'" }
      ]
    },
    {
      "source": "/_astro/(.*)",
      "headers": [{ "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }]
    }
  ]
}
```

هذه CSP في وضع Report-Only لجمع المخالفات، وليست حماية مطبقة. تحتاج اختبار CSS المضمن وخطوط Google وأي خدمات جديدة، ثم تضييق السياسة واستخدام hashes عند الحاجة وتحويلها إلى Content-Security-Policy. frame-ancestors في Report-Only لا يفرض منع التضمين؛ X-Frame-Options أعلاه يطبقه على المتصفحات الداعمة. لا تضف X-XSS-Protection كحل حديث.

### تحسين إضافي

- [ ] فحص دوري للاعتماديات وسلسلة التوريد، ومراجعة الأسرار دون طباعتها، وتحديث السياسة عند إضافة تحليلات أو backend. نموذج واتساب الحالي لا يخزن طلبات في خادم الموقع ولا يعلن نجاح إرسال لم يحدث.

## 5. الذكاء الاصطناعي ومحركات البحث الحديثة

### عاجل

- [x] محتوى الخدمة الأساسي في HTML، وعناوين مباشرة وأقسام بإجابات واضحة وروابط داخلية قابلة للاستخراج.
- [ ] عند الإطلاق، اسمح بالزحف والفهرسة والمقتطفات للصفحات المرغوبة وتحقق من عدم حجب CDN/WAF للزاحف الصحيح. لا تُخفف الأمان أو تلغِ الحماية الشاملة لهذا الغرض.
- [ ] لا تضف nosnippet أو حد مقتطف غير مقصود لصفحات تريد ظهورها في ميزات Google التوليدية. اختيار منع مقتطفات بعينها قرار نشر مستقل.

### متوسط

- [ ] فصل شرح الخدمة عن المقارنة والأسعار والأعطال، وإجابة السؤال أولاً ثم شرح الشروط والاستثناءات. اذكر مصدر التعليمات الفنية وحدود تعميمه على الموديلات.
- [ ] توحيد اسم النشاط ورقم التواصل والخدمات والمناطق المؤكدة، وربط البيانات المنظمة بالمحتوى الظاهر. لا تضف أرقام أعمال أو تقييمات أو اعتماداً غير موثق.
- [ ] ذكر تاريخ تحديث حقيقي واسم مسؤول المراجعة عند توفره. راقب Search Console والزيارات والإحالات، مع إدراك حدود فصل زيارات AI في التقارير.

### تحسين إضافي

- [ ] llms.txt ليس متطلباً لظهور Google AI Overviews أو AI Mode، ولا توجد Schema خاصة تضمنه. إدارة سماح زواحف الشركات الأخرى منفصلة عن Googlebot، وتُراجع بحسب سياسة النشر والتدريب المطلوبة. Google-Extended ليس مفتاح التحكم في الظهور داخل Google Search.

## بوابة قبول الإطلاق

1. دومين مؤكد وHTTPS وتحويلات سليمة؛ لا noindex غير مقصود في الإنتاج، ولا index في نسخ المعاينة.
2. ترقية اعتماديات مخططة ومختبرة ومعالجة أو توثيق المخاطر المتبقية قبل الإطلاق.
3. npm run build ثم npm run seo:check ثم astro check بنجاح؛ فحص النموذج والقائمة والمسارات.
4. جميع الصفحات المستهدفة HTTP 200، والروابط المفقودة 404، والخريطة Canonical فقط؛ اختبار الرؤوس على الاستضافة لا على المعاينة المحلية وحدها.
5. خط أساس Lab موثق، ثم متابعة بيانات الميدان عندما تتوفر عينة كافية؛ لا ادعاء بدرجة سرعة أو ترتيب لم تُقَس.
